<objective>
本 phase 的**不可逆对外动作**：把 `main` 推送到 `origin`（SSH），让 Actions 首次激活，并把「首跑即绿」验成机器结论。

ROADMAP 把「CI 首绿」挂在 `03-01` 名下；本计划把它拆出来的理由只有一个——**push 是单向门**：它会在公开仓库上永久留下 CI 运行历史，且「无红跑历史」是用户的成文判据（D-03 / SC-5）。因此推送**不能**混在一个 `autonomous: true` 的计划里自动执行，必须单独成为一个带 `checkpoint:decision` 的计划。03-01 交付「管线不红的条件」，03-02 交付「发布面材料齐全」，本计划交付「真的推上去且首跑绿」。

三个任务：**Task 1** 在 push 前把全部等价证据一次性复跑（四格 install/probe + 两档 GSD 构建 + actionlint + 全量套件 + 远端 zero-state 核对）——这是把「首跑即绿」从推测压到可观测的唯一手段；**Task 2** 是 `checkpoint:decision`，由人裁决推送通道与时机（SSH / 推迟 / 换通道改凭据）；**Task 3** 执行推送并观测首跑，断言 `conclusion=success` 与 `total_count==1`。

Purpose: PUB-01 的 Phase 3 部分（「GitHub 仓库建仓并推送，repo 名 = npm 包名；npm 首次发布推迟到 Phase 5」）在此闭合——仓已存在，本计划把 88+ 个本地提交与这份 workflow 推上去，并证明首次激活即绿。D-02 的边界同时被守住：**不** publish、**不**建 Release、**不**提 dshmarket PR。

Output: 无源码改动（`files_modified: []`）。产出是**远端状态**与一份证据册 `03-03-SUMMARY.md`。

> **计划级设计决策（已纳入）**：
> - **`autonomous: false` 的原因**：本计划含一个 `checkpoint:decision`（`gate="blocking-human"`，见 Task 2）。按 reversibility 规则，含 checkpoint 的计划必须置 `autonomous: false`。
> - **为什么 gate 是 `blocking-human` 而不是 `blocking`**：这个 checkpoint 存在的唯一理由就是「人必须自己决定要不要把东西推到公网」。若用 `blocking`，auto 模式会替人决定——那正好抹掉了这个门的意义。
> - **为什么 push 前必须重跑一次全量**：03-01/03-02 的会话可能已过去一段时间，且 `build-smoke` 会重写构建树；CI 首跑要用的是**当下这棵树**。四格 + 两档构建 + actionlint + 全量套件是一次不可省的合练。
> - **不做的事（D-02）**：`npm publish`、GitHub Release、dshmarket PR 一律不执行；`private: true` 保留；Phase 5 的移交项（`EPRIVATE` / prerelease `--tag` / `dist-tags.latest` / 包名抢注复查）只在本计划的 SUMMARY 里登记，不在本计划执行。
> - **残余风险（A1）**：CI 首跑本身无法先验证明。若首跑即红，SC-5 已实质未达成（红跑历史已产生）——此时**不许**靠重推掩盖，只能如实上报并把它记为 open 项。
> - **push 前 clean-tree 断言的排除口径（修订：消解「写 SUMMARY」与「断言工作树干净」的自相矛盾）**：Task 1 的最后一步写 `03-03-SUMMARY.md`，而 `<verify>` 在该步之后执行——若无条件断言 `git status --porcelain` 为空，**正确执行也会红**，且红在一个守护单向门的断言上（最坏的一种假阴）。故断言改为**只排除这一个路径**：`git status --porcelain -- . ':(exclude).planning/phases/03-github-npm-dshmarket/03-03-SUMMARY.md'`。排除是安全的，理由有三：① 该文件是**本任务自己的交付物**，不是「未提交的垃圾」，其余任何路径仍然照旧受检（排除是单路径白名单，不是通配）；② 按 `planning.commit_docs: true` 与 execute-plan 的「write and commit SUMMARY.md as one atomic block」，SUMMARY 由**计划收尾的 metadata commit** 提交，任务内提交它会与执行器的 commit 协议冲突——所以它在 Task 1/3 期间**本就应该**是未提交状态；③ push 的实际内容是 `HEAD`，一个尚未写入的 `.planning/` 文档不在被推的树里，CI 不消费它，与 T-03-14（推送的树 == 本地验证的树）无冲突。Task 3 步骤 1 的复核用**同一口径**。
</objective>
